# MNIST replication of the saliency-vs-magnitude comparison

Generated by `python -m train.sweep_mnist` from `results/mnist_summary.json`.

**Dataset actually used: mnist_784 (OpenML).** 10000 train / 2000 test images, a fixed
subset drawn with seed 0 from the canonical split (train from the first 60k rows, test from
the last 10k), pixels scaled x/255 -> [0,1]. The same subset is used for every run; the training seed only
changes weight init and mini-batch order. scikit-learn is used only to download/parse the data.

Model: MLP 784-128-10 (ReLU), 101632 prunable weights. Adam lr=0.001, batch 128,
12 epochs. Same Pruner as spirals (per-layer uniform sparsity, cubic ramp from end of epoch 1 to 60%
of training, prune every half epoch, EMA-0.9 scores, no regrowth). Identical hyperparameters for both criteria;
nothing was tuned per criterion. 20 paired seeds (100..119), 200 runs,
mean 37.1 s per run (7 parallel worker processes, wall-clock
17.9 min).

## Pre-specified confirmatory test: 95% sparsity

The spirals sweep produced a post-hoc, exploratory finding: saliency beat magnitude at 95% sparsity
(spirals: +8.00 pts, CI [+2.67, +12.87], 16/20 seeds). **Before running this sweep, 95% was fixed as the single confirmatory comparison**, on a new dataset
and on fresh seeds. (Setup used seed 0 only, for timing and to pick the epoch count; seed 0 is not in this sweep.)

At 95.0% achieved sparsity, saliency reaches 91.10% +/- 0.42%
test accuracy versus 90.51% +/- 0.63% for magnitude (mean paired difference
+0.59 pts, 95% paired-bootstrap CI [+0.29, +0.89], saliency better on
15/20 seeds, ties 1).

**Replicated.** The 95% CI excludes 0 in the same direction as on spirals (saliency > magnitude).

## Caveats

- Subset of MNIST (10k/2k), small one-hidden-layer MLP, short training; absolute accuracy is below
  full-MNIST numbers. Accuracy is final-epoch test accuracy, no validation-based selection.
- Uniform per-layer sparsity prunes the 128x10 output layer to the same fraction as the input layer;
  at 95% that layer keeps only 64 of 1280 weights,
  which likely dominates the accuracy loss at that level for both criteria.
- One dataset subset; variability across seeds reflects init and batch order, not data sampling.
- Pruner version: `prune/pruner.py` sha256 prefix 4d8b72c4a03d925a, which includes the fix where
  `Pruner.accumulate()` falls back to `p.grad` while nothing is pruned yet (preflight check that scores are
  non-zero before the first prune event: passed). An earlier,
  aborted run of this sweep used the pre-fix pruner, whose first prune event cut arbitrary weights for both
  criteria; those numbers were discarded and are not reported. The file was unchanged during the sweep.
